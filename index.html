Viva & Technical Q&A Cheatsheet

Essential points to explain to professors, examiners, and project evaluators.

✦ Q1. What is the architecture of this project?
This is a Client-Side Single-Page Application (SPA) built using Vanilla HTML5, CSS3, and JavaScript (ES6+) with Chart.js for interactive visualizations. It uses the browser's LocalStorage API for zero-latency, persistent client storage without needing a heavy backend setup.
✦ Q2. How does the Sentiment Analysis work?
It employs a Lexicon-based Natural Language Processing heuristic. The text is normalized (lowercased, punctuation cleaned, and tokenized). We calculate positive and negative keyword matches against a curated dictionary (including English & Hinglish terms). Negation handling checks for prefixes like "not", "never", or "hardly" before a positive word, flipping the polarity!
score = (posWords - negWords) + negationOffset;
if (score > 0) return 'Positive';
if (score < 0) return 'Negative';
return fallbackRatingRating(stars);
✦ Q3. Why use LocalStorage over Cookies or SessionStorage?
LocalStorage provides up to 5MB to 10MB of persistent storage per origin, survives page refreshes and browser restarts, and does not send data overhead with every HTTP request unlike HTTP Cookies (which are capped at 4KB). SessionStorage on the other hand is cleared when the tab closes.
✦ Q4. What are the limitations of keyword-based sentiment analysis?
Keyword matching can struggle with sarcasm (e.g., "Oh great, another broken feature") and complex double negatives. In production environments, this can be upgraded to an LLM or Transformer model (such as BERT or RoBERTa) via Python/FastAPI or HuggingFace API.
✦ Q5. How is Net Promoter Score (NPS) calculated?
NPS measures customer loyalty on a scale from -100 to +100:
NPS = (% Promoters [4★ & 5★]) - (% Detractors [1★ & 2★])
Scores above 0 are considered good, and scores above +50 are world-class!
